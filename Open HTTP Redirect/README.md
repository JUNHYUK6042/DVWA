# Open HTTP Redirect

## 개요

- Open HTTP Redirect는 웹 애플리케이션이 `redirect` 파라미터 값을 검증 없이  
  그대로 리다이렉트에 사용하여 공격자가 사용자를 임의의 외부 사이트로 유도할 수 있는 취약점입니다.
- 정식 분류는 **CWE-601: URL Redirection to Untrusted Site ('Open Redirect')** 이며,  
  OWASP Top 10 2021 기준 **A01: Broken Access Control**에 해당합니다.
- 직접적인 서버 손상은 없지만, 신뢰할 수 있는 도메인을 이용한 피싱 공격의 수단으로 악용됩니다.

---

## Open HTTP Redirect 취약점 유형

| 구분 | 설명 | 특징 |
|------|------|------|
| URL 파라미터 삽입 | redirect 파라미터에 외부 URL을 직접 삽입 | 가장 일반적인 형태, 브라우저에서 바로 확인 가능 |
| URL 인코딩 우회 | 외부 URL을 인코딩하여 필터 우회 | `https%3A%2F%2Fevil.com` 형태로 검증 로직 우회 |
| 상대경로 혼용 | `//evil.com` 형태로 프로토콜 없이 삽입 | 일부 검증 로직이 `http://`만 필터링할 때 우회 가능 |

---

## 핵심 개념

- Open Redirect의 핵심은 **도메인 신뢰 악용**입니다.
- 피해자 입장에서는 링크가 신뢰할 수 있는 도메인(`192.168.11.36`)으로 시작하기 때문에 악성 링크임을 인식하기 어렵습니다.
- 서버가 `redirect` 파라미터 값을 그대로 `Location` 헤더에 넣어 `302 Found`로 응답하면 브라우저는 해당 URL로 자동 이동합니다.

---

## 공격 방식 설명

- 공격자는 신뢰할 수 있는 도메인의 redirect 파라미터를 악성 사이트 URL로 변조한 링크를 피해자에게 전달합니다.
- 피해자가 링크를 클릭하면 서버는 검증 없이 해당 URL로 `302 리다이렉트` 응답을 보내고, 브라우저는 악성 사이트로 이동합니다.
- 피해자는 처음에 신뢰할 수 있는 도메인을 클릭했기 때문에 공격 사실을 인지하기 어렵습니다.

---

## 예시

- 정상 요청  
  → `http://192.168.11.36/DVWA/vulnerabilities/open_redirect/source/low.php?redirect=info.php?id=1`  
  → 내부 페이지로 이동  

- 공격 요청   
  → `http://192.168.11.36/DVWA/vulnerabilities/open_redirect/source/low.php?redirect=https://www.google.com`  
  → 서버 응답: `302 Found` + `Location: https://www.google.com`  
  → 브라우저가 google.com으로 자동 이동  
 
- 실제 공격 시나리오  
  → `http://신뢰도메인.com/redirect?url=https://피싱사이트.com/login`  
  → 피해자가 신뢰도메인 링크를 클릭 → 피싱 사이트로 이동 → 계정 정보 탈취  

---

## 특징

- 서버에 직접적인 손상을 주지 않아 간과하기 쉬운 취약점입니다.
- 신뢰할 수 있는 도메인을 경유하기 때문에 피싱 공격의 성공률이 높아집니다.
- OAuth 인증 흐름에서 `redirect_uri` 파라미터에 이 취약점이 있으면 인증 코드나 토큰이 공격자 서버로 전달될 수 있습니다.
- URL 인코딩, 프로토콜 생략(`//evil.com`) 등 다양한 방식으로 검증 로직을 우회할 수 있습니다.

---

## 대응 방안

- **화이트리스트 기반 검증**: 허용할 리다이렉트 대상 URL 목록을 서버에서 관리하고, 목록에 없는 URL은 리다이렉트를 거부합니다.
- **외부 URL 리다이렉트 차단**: 리다이렉트 대상이 동일 도메인인지 검증하고, 외부 도메인으로의 리다이렉트를 원천 차단합니다.
- **파라미터 직접 사용 금지**: 사용자 입력값을 `Location` 헤더에  
  그대로 사용하지 않고, 서버에서 미리 정의한 URL만 리다이렉트 대상으로 사용합니다.
- **인덱스 방식 사용**: `redirect=1`, `redirect=2`처럼  
  숫자로만 받아 서버에서 매핑된 URL로 이동하여 외부 URL 삽입 자체를 불가능하게 만듭니다.

---

## 정리

- Open HTTP Redirect는 redirect 파라미터 검증 부재로 인해 사용자를 임의의 외부 사이트로 유도하는 취약점입니다.
- CWE-601, OWASP A01:2021(Broken Access Control)에 해당합니다.
- 서버 손상이 없어 위험도를 낮게 평가하기 쉽지만, 피싱 및 OAuth 토큰 탈취 등 심각한 2차 피해로 이어질 수 있습니다.
- 화이트리스트 검증과 인덱스 방식 리다이렉트 적용이 가장 효과적인 대응 방법입니다.
