# Cryptography (암호화 취약점)

## 개요

- Cryptography 취약점은 암호화 키나 패스워드가 소스코드에 하드코딩되어 있거나, 취약한 암호화 알고리즘을 사용할 때 발생합니다.
- 공격자는 소스코드 노출, 알려진 평문 공격, 복호화 오라클 악용 등을 통해 암호문을 복호화하거나 인증을 우회할 수 있습니다.
- 암호화 강도보다 키 관리 방식이 잘못된 경우가 실제 환경에서 더 빈번하게 발생합니다.

---

## 핵심 개념

### XOR 암호화

- 평문과 키를 XOR 연산하여 암호문을 생성하는 방식으로, 동일한 키를 반복 적용합니다.
```
평문  : c r y p t o c a t
키    : w a c h t w o o r
암호문: XOR 결과 (바이트 단위)
```

- 키 길이보다 평문이 길면 키가 반복 순환됩니다.
- 같은 키로 같은 위치의 문자는 항상 같은 암호문이 나오기 때문에 패턴 분석에 취약합니다.

---

### Base64 인코딩

- 바이너리 데이터를 텍스트로 변환하는 인코딩 방식으로, **암호화가 아닙니다.**
```
평문  : cryptocat is the best!
Base64: Y3J5cHRvY2F0IGlzIHRoZSBiZXN0IQ==

-- 디코딩은 누구나 할 수 있음 — 보안 수단이 아님
```

- XOR 암호화 결과를 Base64로 감싸서 전송하는 방식은 Base64가 암호화처럼 보이지만 실제로는 아닙니다.

---

### 알려진 평문 공격 (Known Plaintext Attack)

- 공격자가 평문과 그에 대응하는 암호문을 알고 있을 때, 이를 이용해 키를 복원하는 공격입니다.
```
평문  : cryptocat is the best!
암호문: FBMaGAAYDA4GRB4SQxwcEk8NFxcDQA==

평문 XOR 암호문 → 키 복원
키   : wachtwoord (반복 패턴으로 확인)
```

- XOR 암호화는 `평문 XOR 암호문 = 키`가 성립하기 때문에 알려진 평문 공격에 취약합니다.

---

### 복호화 오라클 (Decryption Oracle)

- 서버가 복호화 기능을 외부에 노출하여, 공격자가 임의의 암호문을 서버에 보내면 복호화 결과를 돌려받을 수 있는 상태입니다.
```
공격자 → 가로챈 암호문 입력 → 서버 Decode 기능 → "Your new password is: Olifant"

-- 서버가 키를 모르는 공격자 대신 복호화를 수행해줌
```

---

### 하드코딩된 암호화 키 / 패스워드

- 키나 패스워드가 소스코드에 직접 작성되어 있어, 소스코드가 노출되면 즉시 탈취됩니다.
```php
$key = "secretkey123";       -- 소스코드에 키 하드코딩
if ($password == "admin1234") -- 소스코드에 패스워드 하드코딩
```

- GitHub 등 코드 저장소에 업로드되거나, 취약한 파일 접근으로 소스코드가 노출되면 즉시 악용 가능합니다.

---

## 공격 흐름

```
[1] 암호문 가로채기
    네트워크 도청 또는 중간자 공격으로 암호화된 메시지 획득

[2] 복호화 오라클 악용
    서버의 복호화 기능에 가로챈 암호문 입력
    → 서버가 대신 복호화하여 평문 반환

[3] 획득한 정보로 인증 우회
    복호화 결과에서 패스워드 확인 후 로그인
    → 인증 우회 성공

[4] 알려진 평문 공격으로 XOR 키 복원
    평문 XOR 암호문 = 키 (수학적 성질 이용)
    → 복원된 키로 해당 키로 암호화된 모든 메시지 복호화 가능
```

---

## 특징

- XOR 암호화는 구현이 단순해 소규모 시스템에서 잘못 사용되는 경우가 많습니다.
- Base64는 암호화가 아닌 인코딩이므로 보안 수단으로 사용하면 안 됩니다.
- 하드코딩된 키는 소스코드 유출, 역공학, 저장소 노출 등 다양한 경로로 탈취됩니다.
- 복호화 기능을 인증 없이 외부에 노출하면 서버 자체가 공격 도구가 됩니다.
- 알려진 평문 공격은 XOR뿐 아니라 ECB 모드 AES 등 다른 취약한 암호화에도 적용됩니다.

---

## 대응 방안

- 검증된 암호화 알고리즘(AES-256-GCM 등)을 사용하고 XOR 같은 단순 암호화는 사용하지 않습니다.
- 암호화 키는 소스코드에 하드코딩하지 않고 환경변수 또는 키 관리 시스템(KMS)에서 불러옵니다.
- 패스워드는 소스코드에 평문으로 저장하지 않고 bcrypt, argon2 같은 안전한 해시 함수로 처리합니다.
- 복호화 기능에 인증 및 권한 검증을 적용하여 외부에서 임의로 호출하지 못하도록 제한합니다.
- 동일한 IV를 재사용하지 않고 매 암호화마다 랜덤 IV를 생성합니다.
