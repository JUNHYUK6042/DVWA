# Authorisation Bypass

## 개요
- Authorisation Bypass(인가 우회)는 인증된 사용자가  
  자신의 권한을 초과하여 다른 사용자 또는 관리자 전용 기능에 접근하는 취약점입니다.
- 서버가 요청에 대한 권한 검증을 제대로 수행하지 않을 경우  
  일반 사용자가 URL 직접 접근, 파라미터 변조 등을 통해 관리자 기능을 사용할 수 있습니다.
- 인증(Authentication)과 인가(Authorization)는 다른 개념으로  
  로그인에 성공했더라도 접근 권한이 없는 기능에 접근할 수 없어야 합니다.

---

## 인증 vs 인가 차이

| 구분 | 설명 | 예시 |
|------|------|------|
| 인증 (Authentication) | 사용자가 누구인지 확인 | 로그인 |
| 인가 (Authorization) | 사용자가 무엇을 할 수 있는지 확인 | 관리자 페이지 접근 권한 |

---

## Authorisation Bypass 취약점 유형

| 구분 | 설명 | 특징 |
|------|------|------|
| URL 직접 접근 | 관리자 전용 URL을 직접 입력 | 서버사이드 권한 검증 부재 |
| 파라미터 변조 | ID, role 등 파라미터 값을 변조 | 클라이언트 사이드 신뢰 문제 |
| 수평적 권한 상승 | 동일 권한 다른 사용자 데이터 접근 | 본인 외 타인 정보 조회·수정 |
| 수직적 권한 상승 | 일반 사용자가 관리자 기능 접근 | 관리자 페이지, DB 조작 등 |

---

## 핵심 개념

- 서버는 모든 요청에 대해 세션 기반 권한 검증을 수행해야 합니다.
- URL만 알면 접근 가능한 구조는 서버사이드 권한 검증이 없는 것입니다.
- 클라이언트에서 권한을 제어하는 방식(숨김 버튼, 비활성화 등)은 우회가 가능합니다.

---

## 공격 방식 설명

- 공격자는 낮은 권한의 계정으로 로그인한 후, 관리자 전용 URL에 직접 접근을 시도합니다.
- 서버가 세션의 권한을 검증하지 않으면 관리자 기능이 그대로 노출됩니다.
- 파라미터에 포함된 사용자 ID나 role 값을 변조하여 다른 사용자의 데이터에 접근할 수도 있습니다.

---

## 예시

- 정상 접근  
  → admin 계정으로 로그인 후 `/admin/users` 접근 가능

- 공격 접근  
  → gordonb 계정으로 로그인 후 `/admin/users` URL 직접 입력  
  → 서버가 권한 검증을 하지 않으면 그대로 접근됨

- 파라미터 변조  
  → `/user?id=1` → `/user?id=2` 로 변조하여 타인 정보 조회

---

## 특징

- 로그인만 되어 있으면 관리자 기능에 접근할 수 있습니다.
- 회원정보, 관리자 데이터 열람 및 수정이 가능합니다.
- 권한 상승을 통해 시스템 전체를 장악할 수 있습니다.
- URL만 알면 공격이 가능하여 진입 장벽이 낮습니다.

---

## 대응 방안

- 모든 페이지와 기능에 대해 서버사이드에서 세션 권한을 검증합니다.
- 관리자 전용 기능은 role 기반 접근 제어(RBAC)를 적용합니다.
- 클라이언트 사이드 권한 제어(UI 숨김 등)에만 의존하지 않습니다.
- 권한 없는 접근 시도에 대한 로깅 및 알림을 설정합니다.
- 최소 권한 원칙을 적용하여 필요한 기능에만 접근을 허용합니다.

---

## 정리

- Authorisation Bypass는 인가 검증 부재로 인해 권한 없는 기능에 접근하는 취약점입니다.
- 로그인 성공 여부와 관계없이 모든 기능에 대한 서버사이드 권한 검증이 필수입니다.
- RBAC 적용과 서버사이드 권한 검증이 가장 효과적인 대응 방법입니다.
