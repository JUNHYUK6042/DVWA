# JavaScript Attacks

## 개요

- JavaScript Attacks는 서버사이드에서 수행해야 할 보안 검증 로직이  
  클라이언트 JavaScript에 노출되어, 공격자가 이를 분석하고 조작하여 서버 측 검증을 우회할 수 있는 취약점입니다.
- 정식 분류는 **CWE-602: Client-Side Enforcement of Server-Side Security**이며,  
  OWASP Top 10 2021 기준 **A04: Insecure Design**에 해당합니다.
- 클라이언트 코드는 공격자가 언제든지 열람하고 수정할 수 있어 보안 로직으로 신뢰할 수 없습니다.

---

## JavaScript Attacks 취약점 유형

| 구분 | 설명 | 특징 |
|------|------|------|
| 토큰 생성 로직 노출 | token 생성 알고리즘이 JavaScript에 그대로 노출 | 공격자가 로직 분석 후 올바른 token 직접 계산 가능 |
| 클라이언트 측 입력 검증 | 입력값 유효성 검사를 JavaScript에서만 수행 | 요청 변조로 서버에 임의 값 전송 가능 |
| 숨겨진 필드 조작 | hidden input 필드 값이 클라이언트에서 수정 가능 | 가격, 수량, 권한 등 변조 가능 |

---

## 핵심 개념

- JavaScript Attacks의 핵심은 **클라이언트를 절대 신뢰하지 않는 것(Never Trust the Client)**입니다.
- 브라우저 개발자 도구나 Burp Suite를 통해 클라이언트 JavaScript 코드를 누구나 열람할 수 있습니다.
- 서버가 클라이언트에서 생성된 값을 검증 없이 신뢰하면, 공격자는 이 값을 조작하여 인증이나 검증을 우회할 수 있습니다.

---

## 공격 방식 설명

- 공격자는 브라우저 개발자 도구(F12) 또는 페이지 소스(Ctrl+U)를 통해 클라이언트 JavaScript 코드를 분석합니다.
- token 생성 로직 등 보안 관련 알고리즘을 파악한 뒤, CyberChef 등 도구로 올바른 값을 직접 계산합니다.
- Burp Suite Intercept로 요청을 가로채 phrase와 token 값을 변조하여 서버에 전송합니다.
- 서버는 변조된 요청을 정상 요청으로 인식하여 인증이나 검증을 통과시킵니다.

---

## 예시

- 정상 흐름  
  → 사용자가 입력창에 값 입력 → JavaScript가 자동으로 `token = md5(rot13(phrase))` 생성 → 서버 전송 → 검증 통과

- 취약한 구조 (DVWA Low 레벨)  
  → `generate_token()` 함수가 클라이언트 소스에 노출  
  → 공격자가 rot13 + MD5 알고리즘 파악  
  → `md5(rot13("success"))` = `38581812b435834ebf84ebcc2c6424d0` 직접 계산  
  → Burp Suite로 `phrase=success&token=38581812b435834ebf84ebcc2c6424d0` 변조 전송  
  → 서버가 "Well done!" 반환  

- 실제 공격 시나리오  
  → 쇼핑몰에서 가격이 hidden 필드로 전달될 경우, 공격자가 Burp Suite로 가격을 0으로 변조하여 결제 우회 가능

---

## 특징

- 클라이언트 JavaScript 코드는 브라우저 개발자 도구로 누구나 열람할 수 있습니다.
- 입력값 변조, hidden 필드 조작, token 위조 등 다양한 방식으로 악용됩니다.
- 실제 환경에서는 가격 조작, 권한 우회, 인증 우회 등 심각한 피해로 이어질 수 있습니다.
- 서버가 클라이언트에서 전달된 값을 재검증하지 않는 경우에만 취약점이 성립합니다.

---

## 대응 방안

- 보안 검증 로직은 반드시 서버사이드에서 구현하고, 클라이언트 JavaScript에 의존하지 않습니다.
- 토큰은 서버에서 생성하여 세션에 저장하고, 제출된 값과 서버 보유 값을 서버사이드에서 비교합니다.
- 클라이언트에서 전달된 모든 값을 신뢰하지 않고 서버에서 재검증합니다.
- hidden 필드, URL 파라미터, 쿠키 등 클라이언트가 조작할 수 있는 데이터를 보안 판단에 사용하지 않습니다.

---

## 정리

- JavaScript Attacks는 클라이언트 코드에 보안 로직이 노출되어 공격자가 이를 분석하고 서버 검증을 우회하는 취약점입니다.
- CWE-602, OWASP A04:2021(Insecure Design)에 해당합니다.
- 핵심은 **클라이언트를 절대 신뢰하지 않는 것**이며, 모든 보안 검증은 서버사이드에서 수행해야 합니다.
